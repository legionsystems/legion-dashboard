# legion-preview-executor

Host-side HTTP service the LEGION Dashboard container calls into to
manipulate git checkouts and `docker compose` runs that cannot happen
from inside the read-only `/srv/repo` mount. It listens on `127.0.0.1:8766`,
authenticates every request with `X-Api-Key`, and is the single
boundary between the dashboard and the host's docker daemon.

The systemd unit lives at [`../systemd/legion-preview-executor.service`](../systemd/legion-preview-executor.service).
Its `ExecStart=` points at this directory:

```
ExecStart=/usr/bin/python3 /srv/repo/legion-dashboard/ops/host-executor/legion-preview-executor
```

So `git pull` on the host repo plus `systemctl restart legion-preview-executor`
is enough to roll forward. There is no longer a separate runtime copy
under `/root/.hermes/LEGION_TOOLS/bin/`.

## Adding a new allowlist root

The executor refuses any `repo_path` that does not resolve under one of
its configured *allowed repo roots*. The defaults baked into source are:

- `/srv/repo/legion-dashboard`
- `/srv/repo/lgn-hub`
- `/srv/worktrees/legion-dashboard`

(The third entry is the per-task worktree tree generated by
`legion-worktree-create`.)

There are two ways to extend the list:

1. **Operator-managed env var (recommended).** Set
   `LEGION_EXECUTOR_ALLOWED_REPO_ROOTS` in
   `/etc/legion/preview-executor.env` to a comma-separated list of
   absolute paths. The env var **replaces** the built-in defaults so
   the operator owns the full list — include the legacy entries you
   still need.

   ```env
   LEGION_EXECUTOR_ALLOWED_REPO_ROOTS=/srv/repo/legion-dashboard,/srv/repo/lgn-hub,/srv/worktrees/legion-dashboard,/srv/repo/lgn-newapp,/srv/worktrees/lgn-newapp
   ```

   The change takes effect on the next
   `systemctl restart legion-preview-executor`.

2. **Edit the source defaults.** Update
   `_DEFAULT_ALLOWED_REPO_ROOTS` in
   `legion-preview-executor`. Use this only when a new root needs to
   ship with every install of LEGION Dashboard; otherwise prefer the
   env-var form so operators don't have to wait for a release to
   onboard a new app.

Whichever path you use, the executor canonicalizes the candidate
`repo_path` with `os.path.realpath` before the prefix check, so
`..`-traversal and symlink escapes cannot smuggle a request past the
gate.

## Configuring the allowlist at runtime

The LEGION Dashboard surfaces the allowlist at
**`/settings/executor-allowlist`** (API: `/api/executor-allowlist`).
The dashboard is the **primary** way to add a new repo root — operators
do not need to ssh into the host for a routine onboarding.

### Precedence (env var wins)

1. **`LEGION_EXECUTOR_ALLOWED_REPO_ROOTS` env var** (set on the
   executor's systemd unit via `/etc/legion/preview-executor.env`):
   the executor reads this verbatim at start and **completely
   replaces** the in-source defaults. When the env var is non-empty,
   the dashboard's persisted list is ignored by the executor.
   The dashboard surfaces an "override active" banner so the operator
   sees this state.
2. **Dashboard-persisted list** (via the UI/API): on each apply, the
   dashboard writes the joined enabled list out to
   `/etc/legion/executor-allowlist.conf` as a systemd
   `EnvironmentFile=` line:

   ```env
   LEGION_EXECUTOR_ALLOWED_REPO_ROOTS=/srv/repo/legion-dashboard,/srv/repo/lgn-hub,...
   ```

   The systemd unit picks up that file via an additional
   `EnvironmentFile=` directive (host operator wires the bind mount
   from `/etc/legion/` into the dashboard container).
3. **In-source defaults**: if neither is set, the executor falls back
   to `_DEFAULT_ALLOWED_REPO_ROOTS`.

### Default roots are seeded

The migration seeds the three in-source defaults
(`/srv/repo/legion-dashboard`, `/srv/repo/lgn-hub`,
`/srv/worktrees/legion-dashboard`) into the dashboard DB on first
run, flagged `is_default = true`. Defaults can be **disabled** via
the UI (so the executor will not match against them on next restart)
but cannot be **deleted** — a fresh install always shows them.

### Apply restarts the executor

The dashboard's `POST /api/executor-allowlist/apply` writes the
config file atomically (tmp + rename) and then runs
`systemctl restart legion-preview-executor`. The result is surfaced
to the operator and recorded in the `executor_allowlist_apply_log`
audit table.

### Add via the UI

Open the dashboard → Settings → Executor Allowlist → Add Root.
Paste the absolute path, add a note explaining why, and click Apply
when ready to restart the service. Validation refuses non-absolute
paths, `..` segments, symlinks, and any path under `/root`, `/etc`,
`/tmp`, `/var`, `/usr`, `/bin`, `/sbin`, `/proc`, `/sys`, `/dev`,
`/boot`, or `/home`.

## EnvironmentFile contract

`/etc/legion/preview-executor.env` is `root:root` mode `0600` and is
provisioned by the host operator. The expected keys:

| Key                                  | Required | Notes                                                       |
| ------------------------------------ | -------- | ----------------------------------------------------------- |
| `API_SERVER_KEY`                     | yes      | Shared secret with the dashboard. Never logged.             |
| `LEGION_EXECUTOR_ALLOWED_REPO_ROOTS` | no       | Comma-separated absolute paths. Replaces baked-in defaults. |
| `LEGION_PREVIEW_EXECUTOR_HOST`       | no       | Default `0.0.0.0`. Bind address.                            |
| `LEGION_PREVIEW_EXECUTOR_PORT`       | no       | Default `8766`. Listen port.                                |
| `LEGION_PREVIEW_EXECUTOR_LOG_LEVEL`  | no       | Default `INFO`.                                             |

## Operational notes

- The executor never `shell=True`-execs and never interpolates
  request-supplied strings into a shell line.
- `branch` is validated against `^[A-Za-z0-9._/\-]{1,200}$` before any
  git call.
- All subprocess calls have explicit timeouts.
- Logs land in `/var/log/legion-preview-executor.log`. Tail it during
  a debug loop with `tail -f` — no sudo required.
